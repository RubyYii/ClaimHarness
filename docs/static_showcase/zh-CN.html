建模前的问题对齐，输出后的证据审计。

这是一个本地优先的中英双语原型：先把文件和模糊的领域问题转成受治理的 ProblemBridge 结果包，再用 ClaimHarness 检查已经存在的文本与声明。

这是只读展示页，不会运行引导式工作台，也不会执行审计。问题对齐请使用本地工作台；证据审计请通过 ClaimHarness CLI 执行。

给非 AI 背景用户

按你现在手里的材料选择入口。你不需要先定义模型、prompt、RAG 系统或 benchmark。

文档摄取层

可以从 DOCX、文字版 PDF、HTML、公开静态网页、粘贴文本、表格或可选本地 OCR 开始。系统保留来源和警告，但不宣称理解文档。

问题发现层

问题还很模糊时，先找出该问什么、该问谁，以及进入方案设计前必须验证哪些未知项。

反复发生的领域工作流

描述判断材料、痛点、专家经验，以及哪些决定绝不能交给 AI 自动完成。

已经存在的文本或结果

声明出现后，再用 ClaimHarness 检查证据链接、缺失要求、过度主张、矛盾和待人工复核事项。

工作流

每一步都会生成可检查的产物并带入下一步，用户不需要反复从空白表单重新开始。

1
文档摄取

提取可审计文本、表格、批注、警告和 problem_seed.md。

2
问题发现

生成问题简报、利益相关者图、访谈指南和待验证未知项。

3
引导式访谈

还原真实工作、材料、痛点、判断方式和人工边界。

4
ProblemBridge

生成 AI 任务规格、证据契约、评价协议和风险计划。

5
证据门控构建

根据证据白名单门控每条候选能力声明，并导出 Codex 交接包。

6
ClaimHarness CLI 审计

审计完成文本，再在静态报告查看器中打开受治理结果包。

当前已更新的功能

新版工作台缩短了步骤之间的路径，同时明确保留项目身份、草稿状态和有风险的操作。

紧凑步骤导航

“上一步 / 当前步骤 / 下一步”在同一个项目会话中切换；窄屏时六步总览横向滑动。

清楚区分新旧结果

历史结果默认折叠，并说明不包含尚未生成的表单修改；摄取、问题发现、对齐和审计分别使用专属视图。

更安全的重置

开始新项目或重置访谈都需要二次确认；开始新项目前可以先保存草稿。

项目身份安全的记忆

加载记忆会恢复原项目身份；“清除记忆”只删除磁盘快照，当前页面草稿仍保留。

可搜索审计查看器

粘性导航、声明搜索、组合筛选、实时计数、声明跳转、可复制复核摘要和展开式证据详情。

本地导出和分享

本地导出 ZIP、Word 和 PDF；分享包默认排除原始上传和未知文件，只有显式选择后才包含原件。

输出、诊断与项目记录

ProblemBridge 结果包

工作流图、痛点矩阵、AI 任务规格、证据契约、评价协议、风险报告、人工复核计划和对齐 trace。

project_record.json · 项目摘要 · revision_history.jsonl，每个目标最多三轮

ClaimHarness 审计包

claim_table.csv、evidence_map.json、audit_report.md、revision_suggestions.md、audit_diagnostics.json 和 human_review_queue.json。每项结果都会把确定性状态和风险，与 human_review_required 及受限的 release_allowed 门分开显示。

待复核队列只是工作待办，不是批准或部署许可

可追溯记录

agent_trace.jsonl、run_manifest.json、project_summary_log.md、run_identity.json 和 run_complete.json 让完成运行可检查。本地哈希快照可以发现已声明生成物后续发生的漂移，但不能阻止篡改。

用于导航和溯源，不是科学证据

本地运行

Windows 最简单的方式是双击 RUN_PROBLEMBRIDGE_WINDOWS.bat。首次运行会创建经过约束的虚拟环境，之后会复用；浏览器没有自动打开时访问 http://127.0.0.1:8501。
git clone https://github.com/RubyYii/ClaimHarness.git
cd ClaimHarness
.\scripts\run_problembridge_ui_powershell.ps1

大多数引导式工作流是确定性的。证据门控构建可以显式选择官方 OpenAI GPT-5.6，逐条核对候选能力声明，并记录 GPT-5.6 是否真实运行。工作台可以查看已有的 ClaimHarness 审计包，但不会替代完整论文审计。

.venv\Scripts\python.exe -m claim_harness demo --out outputs\my_demo_audit
.venv\Scripts\python.exe -m claim_harness view --run outputs\my_demo_audit

安全边界

不要输入真实患者数据、机密论文、API key、未公开项目材料或敏感个人信息。工作台不接收或保存 API key；可选 GPT-5.6 路径只从进程环境读取 OPENAI_API_KEY，并在远程发送前显示提示。
  • 文档摄取只提取文本和表格，不理解图表，也不代替专业判断。
  • OCR 派生文本默认不是强证据，必须人工检查原始文件。
  • ClaimHarness 只检查提供的材料，不保证事实或科学结论正确。
  • 当前合成评测和确定性规则以英文为主；被这些规则判定为高风险的输出必须人工复核，但规则仍可能漏掉高风险声明。
