For non-AI users

Choose the entry that matches what you have now. You do not need to define a model, prompt, RAG system, or benchmark first.

Document Intake Layer

Start from DOCX, text PDF, HTML, a public static webpage, pasted text, tables, or optional local OCR. Extraction preserves source warnings and attention signals without claiming document understanding.

Question Discovery Layer

When the problem is still vague, identify what to ask, who to ask, and which unknowns must be validated before proposing a solution.

Repeated domain workflow

Describe materials, pain points, expert judgement, and decisions that AI must never make automatically.

Existing text or results

Use ClaimHarness after claims exist to inspect evidence links, missing requirements, overclaims, contradictions, and pending human-review work.

Workflow

Each stage creates an inspectable artifact that seeds the next stage instead of forcing users to restart from a blank form.

1
Document intake

Extract auditable text, tables, annotations, warnings, and problem_seed.md.

2
Question discovery

Produce a question brief, stakeholder map, interview guide, and unknowns list.

3
Guided interview

Reconstruct the real workflow, materials, pain points, judgement, and human boundaries.

4
ProblemBridge

Generate the AI task spec, evidence contract, evaluation protocol, and risk plan.

5
ClaimHarness CLI audit

Audit completed text and open the governed package in the static report viewer.

Features now available

The latest workbench shortens the path between stages while keeping project identity, draft state, and destructive actions explicit.

Compact step navigation

Previous/current/next controls preserve one project session; the five-step overview scrolls horizontally on narrow screens.

Clear result context

Previous results stay collapsed and say they do not contain unfinished form edits. Intake, discovery, alignment, and audit packages use their own views.

Safer resets

Starting a project or resetting an interview requires confirmation. Users can save drafts before starting a new project.

Identity-safe memory

Saved memory restores its original project identity. Clear memory removes the disk snapshot while retaining current on-screen drafts.

Searchable audit viewer

Sticky navigation, claim search, combined filters, live counts, direct claim links, copyable review briefs, and expandable evidence details.

Local export and sharing

Export ZIP, Word, and PDF locally. Share archives exclude original uploads and unknown files unless the user explicitly includes originals.

Outputs, diagnostics, and project records

ProblemBridge package

Workflow map, pain-point matrix, AI task specification, evidence contract, evaluation protocol, risk report, human-review plan, and alignment trace.

project_record.json · project summary · revision_history.jsonl with at most three rounds per target

ClaimHarness package

claim_table.csv, evidence_map.json, audit_report.md, revision_suggestions.md, audit_diagnostics.json, and human_review_queue.json. Each result separates deterministic status and risk from human_review_required and the bounded release_allowed gate.

Pending review is a work queue, not approval or deployment permission

Traceability

agent_trace.jsonl, run_manifest.json, project_summary_log.md, run_identity.json, and run_complete.json make completed runs inspectable. Local hash snapshots can reveal later drift in declared generated artifacts; they do not prevent tampering.

Navigation and provenance, not scientific evidence

Run locally

The easiest Windows path is to double-click RUN_PROBLEMBRIDGE_WINDOWS.bat. First setup creates the tested virtual environment; later launches reuse it. If the browser does not open, visit http://127.0.0.1:8501.
git clone https://github.com/RubyYii/ClaimHarness.git
cd ClaimHarness
.\scripts\run_problembridge_ui_powershell.ps1

The guided UI runs deterministic mock workflows only. The workbench can inspect existing ClaimHarness audit packages, but it does not execute or replace an audit. Evidence-contract selection and remote advisory providers also remain CLI-only.

.venv\Scripts\python.exe -m claim_harness demo --out outputs\my_demo_audit
.venv\Scripts\python.exe -m claim_harness view --run outputs\my_demo_audit

Safety boundary

Do not enter real patient data, confidential manuscripts, API keys, unpublished project materials, or sensitive personal information. The workbench is mock-only and does not accept API keys; remote advisory providers are ClaimHarness CLI-only.
  • Document intake extracts text and tables; it does not understand figures or make professional judgements.
  • OCR-derived text is not strong evidence by default and requires inspection of the original source.
  • ClaimHarness checks only the supplied material and does not guarantee factual or scientific correctness.
  • The current synthetic evaluation and deterministic rules are English-first; outputs classified by those rules as high-risk require human review, but the rules may miss high-risk claims.
