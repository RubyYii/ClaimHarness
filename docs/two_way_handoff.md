# 一次双向交接：本地原型与走查

入口：启动工作台，确认一份需求后，在“带走说明”点击“和合作者完成一次双向交接”，或选择侧栏“双向交接”。同一台电脑或共享屏幕轮流操作；A 是领域参与者，B 是技术协作者。称呼与角色由操作者填写，不是账号认证。

具体业务场景留待 formative 后确定。下面的合成例子只用于熟悉操作，不是预先选定的正式实验任务。

## 两个人怎样完成一次交接

1. **A 准备说明。** 从实际工作、困难、期望结果和材料开始，确认表述。此时仅代表 A 确认自己的意思。
2. **B 接收并回应。** 阅读当前版本，填写自己的理解、建议做法与限制、需要 A 回应的地方。建议与问题可以留空。可以保存草稿，重新打开后继续；草稿不算发出回应。
3. **A 回应与调整。** 阅读 B 的原话，写明如何处理、依据与下一步。确有需要时勾选修改目标或期望结果；保留原目标也是有效选择。未解决事项预填并保留；清空时需明确确认本轮没有待解决事项。
4. **B 查看调整结果。** 查看 A 的回应、调整前后、保留问题与下一步，单独记录“可以继续”“部分可以继续”或“仍需讨论”。后两者必须说明原因。需要继续讨论时，B 可以再发起一轮回应。
5. **对照小样例检查。** 在“样例与检查”中，A 从已确认表述里选取关键要求并说明检查方法；B 粘贴或上传一个小型文字、Markdown 或 CSV 结果；A 或 B 逐条记录检查方法、样例位置、观察和结论。

每次 A 确认回应都保存新版本及新版交接说明，目标可以保持原样。双方对旧版本的确认不会沿用到新版本。选取、重新确认或撤回要求也会产生新版本，因此建议先处理说明和关键要求，再由双方核对最终工作版本、保存样例。版本变化后，旧样例与检查仍留在历史中，需要为新版本重新带回和检查样例。

未解决事项可以与“当前范围可以继续”同时存在。“双方可以继续”不代表完全一致、所有问题解决或结果正确。每个人通过当前所选角色记录自己的判断；角色切换本身不代表另一人已经参与。

## 一个合成走查例子

- A：“汇总这些地点的平均水平，希望每个地点同等重要。”
- B：“我理解为先求各地点均值，再求总体均值。不同地点记录数量不一样；缺失记录如何标记？”
- A：解释用途，确认平均口径；将缺失标记保留为待讨论事项，安排 B 先返回两地点的小样例。
- B：核对 A 的回应，选择可以继续或部分可以继续，并注明适用范围。
- A：选取“每个地点同等重要”为关键要求；若要求曾因回应更新而失效，则重新确认。双方再次核对当前版本。
- B：保存 `site,mean` 小表格，例如 North=10、South=20、All=15。
- A：对照手算 `(10+20)/2=15`，注明表格位置并保存检查。该检查只说明这个样例的这项要求。

程序不执行上传文件，不要求参与者从零写代码，不调用模型，也不自动发送给他人。图片、PDF 等样例目前可用文字说明替代；这个入口只接收 UTF-8 TXT、Markdown、CSV，每份不超过 2 MB。

## 数据保存与恢复

- 工作说明继续使用 `outputs/ui_runs/` 中不可覆盖的版本目录，保留四份中英交接说明。
- B 的回应、个人核对、显式保存的草稿与样例索引保存在工作区 `.continuity/` 的哈希串联日志中。
- A 的回应、B 的原话引用、前后变化与待解决事项保存在新版本 `problem_record.json` 的 `continuation` 中；最终日志回执写入失败时，已完成版本仍可恢复这次回应。
- 样例保存在工作区 `handoff_samples/`，保留内容指纹。文件被修改或丢失时，旧检查不再适用。
- 旧页面提交会被拒绝；“重新载入交接记录”刷新讨论，“打开最新版本”切换说明。两者都需要操作者重新核对内容。
- “已保存历史与导出”可下载 JSON，包含当前说明、完整交接日志和当前版要求检查。样例可另行下载；分享完整目录前核对其中的草稿与历史内容。
- 网页刷新后重新进入“双向交接”即可继续已保存记录。未显式保存的浏览器输入不保证跨刷新恢复。

## 第一轮走查观察什么

观察两个人是否能找到下一步、辨别对方原话与自己的回应、说明为何改变或保留设计、保留分歧，并找到小样例对应的要求。记录卡住的位置和需要研究者提示的次数。先让参与者真实操作和交谈，再询问“哪里没有表达出你的意思”“哪里还不理解伙伴的设计”。

该原型提供可追溯操作，不自动判断交流质量或设计质量。TPACK、正式人机协作量表与正式对照实验不在此入口自动施测。没有 AI 参与时，不把本轮体验当作人机协作结果。

## 实现与测试入口

`problem_bridge/dyad.py` 处理角色记录、版本绑定与样例保存；`dyad_ui.py` 提供界面。复用现有反馈事务锁、不可覆盖需求版本、要求选取与检查功能。历史反馈讨论和 ClaimHarness 证据核查仍独立可用。

```powershell
.venv\Scripts\python.exe -m streamlit run apps/problem_bridge_wizard.py
.venv\Scripts\python.exe -X utf8 -m pytest tests/test_dyad_handoff.py tests/test_dyad_ui.py
```

本地测试和自动界面走查不等于真实双人测试；后者需要实际招募参与者。
